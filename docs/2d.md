# 2D

Bevy 0.20's 2D in TSX: a `Camera2d`, flat meshes and their `ColorMaterial`, sprites, and picking.
Rust components keep their Rust field names (`<Sprite custom_size>`); intrinsics take camelCase
props, as `<mesh>` does. `examples/shapes-2d` shows each working row; 2D does not show in the
editor's 3D view, so run it with `bevy-ts dev src/game.tsx` from that folder, or switch the
editor's viewport to the game view (`viewport_mode { camera: "game" }`, [viewport](viewport.md)).

```tsx
<>
  <entity><Camera2d /></entity>
  <entity>
    <Transform translation={[-150, 0, 0]} />
    <mesh2d shape="circle" radius={50} />
    <material2d color="#f80" alpha={0.8} />
  </entity>
  <entity>
    <Sprite image="hero.png" flip_x />
  </entity>
</>
```

## Pixel art

Set `"imageSampler": "nearest"` in `bevy-ts.json`, so every sprite samples its texels whole
instead of blurring them ([assets](assets.md#the-projects-default-sampler)). An image given its own
sampler keeps it.

## `<mesh2d>` and `<material2d>`

`<mesh2d shape>` builds a `Mesh2d` from one of `<mesh>`'s 2D shapes (`circle`, `circularSector`,
`circularSegment`, `ellipse`, `annulus`, `rectangle`, `rhombus`, `regularPolygon`, `triangle2d`,
`capsule2d`, `convexPolygon`), with the same props and checks ([meshes.md](meshes.md)). It is flat
in the XY plane facing +Z, so it takes no `depth` or `segments`. Equal props share one mesh asset,
also with a `<mesh>` of the same shape. `color` is a shorthand for `<material2d color>`.

`<material2d>` is a `ColorMaterial`:

| prop | Bevy | |
|---|---|---|
| `color` | `color` | any colour form; default white |
| `alpha` | the colour's alpha | 0 to 1 |
| `alphaMode` | `alpha_mode: AlphaMode2d` | `"opaque"`, `"blend"` or `{ mask: n }`; unset, `"blend"` below alpha 1, else `"opaque"` |
| `texture` | `texture` | an asset path |
| `uvTransform` | `uv_transform` | `{ scale?, rotation?, translation? }`, as on `<material>` |

Equal props share one material. Props cannot be bindings. Bevy keeps 2D and 3D apart, so
`<mesh2d>` pairs with `<material2d>` and `<mesh>` with `<material>`: mixing them on one entity
fails the load at the element. The code is `crates/bevy-ts-tsx/src/intrinsics.rs`; the types are
`Mesh2dProps` and `Material2dProps` in `bevy-ts/jsx-runtime`.

## Sprites

`Sprite` is Bevy's component, so its props are its Rust fields in Bevy's reflected form:

| prop | TS |
|---|---|
| `image` | an asset path |
| `color` | any colour form |
| `flip_x`, `flip_y` | booleans |
| `custom_size` | `[w, h]` |
| `rect` | `{ min: [x, y], max: [x, y] }`, a region of the image in pixels |
| `image_mode` | `"Auto"`, `{ Scale: "FitCenter" }`, `{ Sliced: { border: { min_inset, max_inset }, center_scale_mode, sides_scale_mode, max_corner_scale } }`, `{ Tiled: { tile_x, tile_y, stretch_value } }`, or UI's `sliced({ border: 8 })` and `tiled(...)`, which return those |
| `alpha_mode` | `"Opaque"`, `"Blend"` or `{ Mask: n }` |

`<Anchor value={[-0.5, 0.5]} />` moves the sprite's origin to its top left. A sprite takes pointer
events on its entity through Bevy's sprite picking; a `<mesh2d>` takes them once `meshPicking` is
on in `bevy-ts.json`.

## Atlases

A sprite sheet is a grid layout and a tile:

```tsx
import { Sprite, TextureAtlasLayout } from "bevy-ts/bevy";

const sheet = TextureAtlasLayout.fromGrid({ tileSize: [32, 32], columns: 4, rows: 1 });

<Sprite image="sheet.png" texture_atlas={{ layout: sheet, index: 2 }} />
```

`fromGrid` is Bevy's `TextureAtlasLayout::from_grid` (`tileSize`, `columns`, `rows`, and
`padding` and `offset`, in whole pixels). It is an asset value, so every slot given an equal grid
shares one layout, `<image atlas={{ layout: sheet, index }}>` too. An `index` past the grid's
tiles fails the load, naming both.

A TS system animates a sheet as Bevy's `sprite_sheet` example does: a timer on the sprite, and
the next tile when it finishes.

```tsx
export class Frames extends Component {
  timer = Timer.fromSeconds(0.1, "Repeating");
  last: u32 = 3;
}

export function animate(time: Res<Time>, sheets: Query<[Mut<Sprite>, Mut<Frames>]>) {
  for (const [sprite, frames] of sheets) {
    if (!frames.timer.tick(time.delta_secs).just_finished) continue;
    const atlas = sprite.texture_atlas;
    if (!atlas) continue;
    atlas.index = atlas.index === frames.last ? 0 : atlas.index + 1;
  }
}
app.addSystems(FixedUpdate, animate);
```

`sprite.texture_atlas` is a copy; changing it on a `Mut` row writes it back at the end of the run
([native](native.md#reflected-rows-in-ts-systems)). Its `index` reads as a number, and takes a number
or a string.

## Y-sort

`<YSort />` draws an entity by its base y within a layer: lower on screen is in front, as
characters walk past trees and each other.

```tsx
import { Sprite, YSort } from "bevy-ts/bevy";

<entity>
  <Transform translation={[x, y, 0]} />
  <Sprite image="hero.png" />
  <YSort layer={1} offset={-8} />
  <entity>
    <Transform translation={[0, -8, -0.00001]} />
    <Sprite image="shadow.png" />
  </entity>
</entity>
```

It sets the entity's `Transform` z, before Bevy propagates transforms, to

    z = layer - clamp(y + offset, -49999, 49999) × 0.00001

- `y` is the entity's own `Transform` y: its world y at the root, its y in its parent's space under
  a parent (its z then adds to the parent's, so it sorts among its siblings). Y-sort is meant for
  roots and for siblings under one still parent.
- `offset` moves the base from the origin to the feet: `-8` for a 16 px sprite centred on its
  origin.
- `layer` is the whole layer it draws in, from -127 to 127: ground at 0, characters and trees at
  1, roofs at 2. Layers never mix. A layer past 127 logs an error naming `YSort.layer` and the
  value, and leaves z alone.
- Past ±49,999 px of base y, sprites tie and draw in no set order; the first time an entity goes
  there, a warning names it.
- A child without `YSort` keeps its own z, added to its parent's: one pixel of y is 0.00001, so a
  shadow at local z -0.00001 draws behind its character and in front of what stands two pixels or
  more further up.
- `YSort` owns `Transform` z: a script's write to z is overwritten the same frame, so write
  `layer`. A level saved from the world holds the derived z beside `YSort`, and loading it
  recomputes z on the first frame: the saved z decides nothing.
- `GlobalTransform` is Bevy's own propagation of the `Transform`, so picking and every other reader
  see what is drawn. A bound y draws at its new z the same frame. A still entity's `Transform` is
  not written again, so it costs a read and a compare; with no `YSort` in the world the pass does
  not run.
- A Rust app adds `bevy_ts_material::Pixel2dPlugin` beside `DefaultPlugins`; the pass is
  `Pixel2dSystems`, in `PostUpdate` before `TransformSystems::Propagate`.

## Screen-size sprites

`<ScreenSize />` keeps a sprite one size on screen at every zoom: a marker over a building reads
the same at 1x and 4x, while it stays in the world, y-sorted and pickable.

```tsx
<entity>
  <Transform translation={[120, 64, 0]} />
  <Sprite image="marker.png" />
  <ScreenSize />
</entity>
```

- It sets `Transform` scale x and y to `scale` (default 1) times the ruling camera's orthographic
  scale, before Bevy propagates transforms: at `Projection` scale 0.25 (zoom 4) a marker's scale is
  0.25, so each image pixel is one screen pixel. `scale={2}` makes each two.
- The ruling camera is the first `Camera2d` by `Camera.order`, then by entity. With none, nothing
  is written.
- Its children scale with it, about its origin. Under a scaled parent the parent's scale multiplies
  in.
- `ScreenSize` owns `Transform` scale x and y, as `YSort` owns z: a script's write is overwritten
  the same frame, so write `scale`. z scale stays the entity's own.
- Sprite picking reads Bevy's `GlobalTransform`, so a click hits the drawn size.

## Text

`<text2d>` is Bevy's `Text2d` on its entity, placed by the entity's `Transform` in pixels:

```tsx
<entity>
  <Transform translation={[0, 40, 0]} />
  <text2d size={24} color="#fff" anchor={[0, -0.5]}>
    Score {() => score()}<span color="#f44">!</span>
  </text2d>
</entity>
```

It takes `<text>`'s props (`size`, `color`, `font`, `weight`, `italic`, `justify`, `linebreak`,
`lineHeight`, `letterSpacing`, `textBackground`, `underline`, `strikethrough`, and `textShadow`,
which writes `Text2dShadow` with y up), and its children the same way: strings, bindings and
`<span>`s, each `<span>` a child entity. It adds `anchor` (`Anchor`: a side, a corner or `[x, y]`
from -0.5 to 0.5) and `bounds` (`TextBounds`: `[width, height]` in pixels, either `null`). Props
and children bind, and a change writes only its component. It is no UI node, so it takes no
`style`.
