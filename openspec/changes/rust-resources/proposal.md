## Why

A TS system cannot take `Res<R>` or `ResMut<R>` of a Rust resource. Only `Time` works, through a special case. Every other name fails the load with "no resource named R", though the `ts-systems` spec already promises it ("A Rust resource with a native layout SHALL be reachable the same way"). Research (`docs/research/rust-resources.md`) found three gaps on one seam; the zero-copy row, the native layouts and the change ticks this needs exist already.

## What Changes

- **Rust resources resolve as `Res`/`ResMut`.** A resource name a TS system names resolves to a TS resource first, then to a layout-tier Rust resource in `NativeLayouts`, by type path or unambiguous short name, as query data does. The run uses the existing `RunParam::Res` path: the frame points at the resource's own row, and `ResMut` marks its change tick. No copy.
- **Refusals at load, each naming the resource:** a reflect-tier resource (with the tier's reason; reflect-tier `Res` belongs to reflect-coverage), a Rust component that is not a resource, `ResMut` of an immutable type, an ambiguous short name, an unknown name.
- **A missing resource, as Bevy.** `Res<R>`/`ResMut<R>` of an absent resource fails the run with its name, as Bevy's `Res<T>` fails validation and panics. `Option<Res<R>>` and `Option<ResMut<R>>` are new params, for TS and Rust resources alike: `undefined` when absent, and the system runs. `runIf(resourceExists(R))` keeps working.
- **`bevy-ts/bevy` ships layout-tier resources** as `Resource` classes (`GlobalAmbientLight`, `UiScale`), with the components' naming rule: the short name, crate-prefixed when two types share it. A new `nativeResource(name, fields)` in `bevy-ts` is the resource sibling of `nativeComponent`; native crates ship their resources with it.
- **Native crates register derive-only resources** with `app.ts_resource_layout::<T>()`, the resource sibling of `ts_layout::<T>()`. Reflected resources need nothing.
- **`Time` stays special.** Its route to `RunParam::Time` is script-time's (`docs/research/script-time.md` §1, §5), and they chose not to fold it onto this path: `Time<Virtual>` and `Time<Fixed>` are all `Duration`s, holes here. The generic path never sees a `Time`.
- **Spec text fixed:** `ts-systems` "Resources" stops citing `Res<Time>` as the Rust example; `native-components` states which resources are columns and how they are named.
- **A coverage table** in `docs/native.md`: every Bevy resource, its tier and its owner.

Out of scope, each owned elsewhere:
- Reflect-tier `Res`/`ResMut` (`ClearColor`, shadow-map sizes, `GlobalAmbientLight.color`): reflect-enums-color, reflect-coverage stage 3, which waits on the operator's go.
- `Time` semantics, `Time<Real/Virtual/Fixed>`, timers: script-time.
- Input resources as typed params with Bevy's methods (`ButtonInput<*>`, touches, gamepads): script-input-devices.
- `Assets<T>` and any resource whose API is methods (`Time<Virtual>::pause`): writable-native-params.

Dependents: script-input-devices (`AccumulatedMouseMotion`, `AccumulatedMouseScroll`, `MouseScrollPixelsPerLine`) and script-time (`Time<Real/Virtual/Fixed>` reads) ride this `Res<T>`. They document and test those resources; this change does not.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `ts-systems`: "Resources" gains Rust resources by name, the refusals, the missing-resource rule and `Option<Res<R>>`/`Option<ResMut<R>>`.
- `native-components`: a new requirement for layout-tier Rust resources: classes in `bevy-ts/bevy` and `native.d.ts`, `nativeResource`, `ts_resource_layout`.

## Impact

- Ask-first: none. No new dependency or service. No new pattern: `nativeResource` and `ts_resource_layout` are siblings of `nativeComponent` and `ts_layout`. Performance: a Rust resource costs what a TS resource costs today (one row pointer per run, no copy); resolution is at load.
- Code: `crates/bevy-ts/src/systems.rs` (resolution, refusals, optional frames), `layout.rs` and `layout_reflect.rs` (a `resource` flag on `NativeComponent`), `crates/bevy-ts-native/src/lib.rs` (`ts_resource_layout`), `crates/bevy-ts-cli/src/reader.rs` (`Option<Res<R>>`), `types.rs` (resource classes in `bevy-ts/bevy`), `crates/bevy-ts-v8/js/core.js` and `packages/bevy-ts/runtime/core.js` (`nativeResource`, optional frames), `packages/bevy-ts/index.d.ts` (`Option` over `Res`/`ResMut`), `bevy-ts/bevy` regenerated by `scripts/gen-bevy-types.sh`.
- Docs: `docs/native.md` (coverage table, using a Rust resource, `Option<Res<R>>`).
- Tests: read, write and change detection against a Rust system; each refusal; a missing resource with and without `Option`; a derive-only resource from a native crate.
