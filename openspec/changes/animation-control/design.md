## Context

`bevy-ts-animation` plays `PlayAnimation` the `many_foxes` way: one `SharedGraph`, an `AnimationTransitions` per player, `AnimationTargets` on the root listing its players. research.md measured what each Bevy control costs: pause and speed 0 sample and write every bone; `stop_all` and removing `AnimationGraphHandle` skip it (about 1 ms of update and 75 CPU points at 400 foxes); hiding saves only GPU. Bevy 0.20 has no visibility culling for animation.

The crate and the `scene-animation` spec were script-gltf's; lead@script-gltf settled the shared items with lead@animation-control on 2026-10-23, and they are now ours.

## Goals / Non-Goals

**Goals:**
- A paused root costs nothing per frame; an off-screen root can opt into the same.
- TS and TSX reach every animation control Bevy has, by clip path, never by an index into the shared graph.
- Stage 2: TS builds an `AnimationGraph` (clips, blends, additive blends, weights, masks) with Bevy's builder, and a root plays it. The reflected-coverage hole for `AnimationGraph.graph` closes.
- Stage 2: TS builds an `AnimationClip` from Bevy's curves and eases, and any entity plays it: translate, rotate, scale and fade over N seconds with no per-frame JS.
- Measured: fox bench arms and agent town's 100 villagers, before and after.

**Non-Goals:**
- Cross-fading from one `graph` to another, or a graph per player under one root.
- Clip events from TS (`add_event`): Bevy's take a typed Rust `EntityEvent`, and TS cannot observe a Rust event yet. A Rust crate adds them to a clip it builds.
- Animating an asset's field (a `StandardMaterial`'s `base_color`): Bevy's clips write components only. Fades go through `MaterialAlpha.alpha`.
- Culling by default, distance LOD, or advancing a parked clip's time.
- Exposing raw `AnimationPlayer` to TS systems. That is reflect-coverage stage 3, and its node-keyed map would still not be path-keyed.

## Decisions

1. **Park by removing `AnimationGraphHandle`.** `advance_animations` and `animate_targets` need it, so without it Bevy neither advances nor writes; the player keeps seek time, weights and transitions. Over `stop_all`: an exact resume, and no restart at 0. Over removing `AnimationPlayer`: no state lost. Cost: one archetype move per player each way, only on a change.
2. **One park system, a decision per root.** In `PostUpdate`, after `apply_changed`, before `AnimationSystems`: `parked = paused || (cull && meshes non-empty && no mesh has ViewVisibility)`. It compares with whether the first player has the handle, and removes or inserts on every player when they differ. It queries only roots with `paused` or `cull` true, plus roots whose `PlayAnimation` changed (to wake one whose flags were cleared), so the default costs nothing. `stop_removed` inserts the handle back on a parked root's players.
3. **`paused` also calls `pause_all`.** Parking alone stops the work; `pause_all` keeps Bevy's own state true for anything reading `is_paused` (and `status().paused`), and costs nothing more.
4. **Meshes recorded with the players.** `AnimationTargets` gains `meshes: Vec<Entity>`, every descendant with `Mesh3d`, filled in `start` from the same walk (the walk stays `players`; a second function `meshes` beside it, both owned here). A TSX child mesh counts: if it is seen, the root is seen. Recording once avoids a per-frame tree walk; a respawned scene re-records in `start`.
5. **Previous frame's visibility.** `ViewVisibility` is computed in `PostUpdate` after propagation, so the park system reads last frame's. A waking root shows one stale frame, as Unity's `CullUpdateTransforms` does. Running after visibility would need animation after propagation, which Bevy does not do.
6. **`repeat` takes Bevy's `RepeatAnimation`.** Bevy's own type gives `Count(n)` with no new field. It is reflected and registered by `AnimationPlugin`. It becomes a hole for TS systems (an enum with data); a column bool plus count would be a second spelling of one concept.
7. **`speed` 0 stays Bevy's.** Parking on speed 0 would change Bevy's meaning and surprise a game that animates speed through 0. Docs point to `paused`.
8. **`Animations` is an exported param, keyed by root.** A path-keyed read needs logic (root to players, clip to node to `ActiveAnimation`), which the generic reflected path cannot give without node indices. Exported-param args take no strings, so the key is the root, which names its clip by path. `status` is read-only and works today; `seek`, `rewind`, `replay` need `Query<&mut AnimationPlayer>`, which writable-native-params allows. Module `bevy-ts/animation`, registered by every engine as `Cameras` is. The param holds `Query<(&PlayAnimation, &AnimationTargets)>`, `Query<(&AnimationPlayer, Has<AnimationGraphHandle>)>` (mut for the writers), `Res<SharedGraph>` and `Res<Assets<AnimationClip>>`.
9. **`seek` is `seek_to`.** Events between the old and new time fire, Bevy's documented seek. `set_seek_time` stays Rust.

## Stage 2: AnimationGraph from TS

Bevy's `AnimationGraph` is a reflected asset whose `graph` (a petgraph `DiGraph`, no `Default`, no reflected serde) reflection cannot reach; the hole check marks it. Bevy already has a path-keyed form of it: `SerializedAnimationGraph`, the `.animgraph.ron` loader's shape, with each clip an `AssetPath`.

10. **The builder is a TS value, not host calls.** `AnimationGraph` in `bevy-ts/bevy` is a hand-written class with Bevy's builder methods, camelCased as exported methods are (`addClip`, `addBlend`, `addAdditiveBlend`, the `*WithMask` forms, `addClips`, `fromClip`, `fromClips`, `addEdge`, `removeEdge`, `get`, `nodes`, `addTargetToMaskGroup`), holding the serialized shape as JSON. It is an asset value (reflect-assets' `AssetValue<AnimationGraph>`), so it goes where any asset goes: a TSX prop, `assets.add`, `assets.set`. The generator emits it in place of a generated class for this one type. *Alternative:* an exported param `AnimationGraphs` with host methods. Rejected: exported-param args take no strings, so no clip path, and building would cost a host call per node.
11. **Node numbers are returned, as Bevy returns them.** Bevy's `add_*` return the new `AnimationNodeIndex`, and the next `add_*` takes it as `parent`; the builder has no other way to say where a node goes. So TS gets a number, local to the graph value it is building, and never one of `SharedGraph`'s. Status, seek and parking stay keyed by root. *Alternative:* a nested tree literal with no numbers. Rejected: it is not Bevy's shape, and cannot say `add_edge` (a node under two parents).
12. **A hand-map in the reflected-asset writer and reader.** One entry in reflect-assets' hand-map list (as `Image.sampler`). Its read and write take reflect-assets' `&Slots` (the type registry, `server: Option<&AssetServer>`, the assets, and the check flag), not `&World`. Write deserializes `SerializedAnimationGraph` from the JSON and loads each clip path through `slots.server`; in check mode (`server` is `None`) it validates the form only and loads nothing; read is Bevy's `TryFrom<AnimationGraph>`, which fails on a clip with no path, named by node. `mask_groups` is keyed by `AnimationTargetId`, a blake3 of the bone path TS cannot compute, so the JSON carries `[target, mask]` pairs and a target is a UUID string or `{ names: [...] }` (`AnimationTargetId.fromNames`), turned into Bevy's id by `from_names`. Reads give UUIDs. The list stays reflect-assets'; the entry and its test are ours. That clears the `UNCOVERED` entry for `AnimationGraph`.
13. **`PlayAnimation.graph`, one owner of a root's graph handle.** `graph: Handle<AnimationGraph>` (default none) beside `clip`. One function, `graph_of(play, shared)`, gives a root's handle (its `graph`, else `SharedGraph`'s), and `start`, `park` and `stop_removed` all call it; today they each read `shared.handle`. The player walk stays `players`/`players_in`. A graph root plays every clip node (`graph.nodes()` filtered to `Clip`), as Bevy's `animation_masks` example does; `AnimationTransitions` stays on the players but goes unused. `SharedGraph` is untouched: roots without `graph` behave exactly as in stage 1.
14. **Edits apply from the asset.** Bevy's evaluator reads the graph asset each frame, so a changed weight or mask needs nothing from us. On `AssetEvent::Modified` for a graph a root uses, Rust starts clip nodes not yet playing and stops ones gone. A changed `graph` field restarts (`stop_all`, play all), no fade.
15. **No writable-native-params.** Building is pure TS and the graph reaches Rust through reflection (`PlayAnimation.graph`, `assets.add`/`set`). Stage 2 depends instead on reflect-assets stage 1 (`assets`, asset values in handle slots, the hand-map list) and on the hole check landing. The `.animgraph.ron` path works without either and is built first.

## Stage 2: AnimationClip from TS

Bevy has no tween component; it tweens with an `AnimationClip` of curves. `AnimationClip` is a reflected asset whose `curves` are `reflect(ignore)` boxed `AnimationCurve`s, so reflection cannot build one. Its curves are `AnimatableCurve::new(animated_field!(C::field), curve)`, `curve` any `Curve<A>` that is `Clone + Debug + Reflect`, `A` an `Animatable` (`f32`, `Vec2`, `Vec3`, `Vec3A`, `Vec4`, `Quat`, `Rot2`, `bool`, `Transform`, `LinearRgba`, `Srgba`, `Laba`, `Oklaba`, `Xyza`, the `f64` forms). A curve's target is an entity with `AnimationTargetId` and `AnimatedBy(player)`. Today `PlayAnimation` starts only on a glTF root's `WorldInstanceReady`, and nothing gives a plain entity a player or a target id.

16. **The builder is a TS value, as the graph's is.** `AnimationClip` in `bevy-ts/bevy` is a hand-written class: `new AnimationClip()`, `addCurveToTarget(target, curve)`, `setDuration(secs)`, `duration`. A curve is `new AnimatableCurve(animatedField(Transform, "translation"), c)`; `animatedField(Component, field)` is Bevy's `animated_field!(Component::field)`, typed against the class's fields so a wrong name or a non-animatable type fails `tsc`. `c` is built from Bevy's constructors, each a class of the same name: `EasingCurve(start, end, ease)` with `EaseFunction` written as Bevy names its variants (`"CubicOut"`, `{ Steps: [4, "End"] }`, `{ Elastic: 2 }`), `ConstantCurve(domain, value)`, `SampleAutoCurve(domain, samples)`, `UnevenSampleAutoCurve(pairs)`, `AnimatableKeyframeCurve(pairs)`, the keyframe curves glTF uses (`SteppedKeyframeCurve`, `CubicKeyframeCurve`, `CubicRotationCurve`), and the splines' `toCurve()`/`toCurveCyclic()` (`CubicBezier`, `CubicHermite`, `CubicCardinalSpline`, `CubicBSpline`, `CubicNurbs`, `LinearSpline`). Each curve has Bevy's adaptors that need no closure: `reparametrizeLinear(domain)` (how an ease over 0..1 becomes N seconds), `reverse()`, `repeat(n)`, `forever()`, `pingPong()`, `chain(other)`, `chainContinue(other)`. `interval(start, end)` is Bevy's. Building makes no host call.
17. **One Rust curve type mirrors the JSON.** `ScriptCurve<A>` is an enum, one variant per constructor and adaptor above, each holding Bevy's own curve (adaptors box their inner `ScriptCurve`). It implements `Curve<A>` by delegating, and `Clone`, `Debug` and `Reflect` (`opaque`), so it is an `AnimationCompatibleCurve`. Bevy samples Bevy's curves; we only dispatch. Closure curves (`FunctionCurve`, `map`, `reparametrize`, `SampleCurve` with a custom interpolation) stay Rust. *Alternative:* `Box<dyn Curve<A>>`. Rejected: not `Clone` or `Reflect`.
18. **A reflected field property, with Bevy's evaluator id.** `animated_field!` is a compile-time closure. `ReflectedField<A>` implements Bevy's `AnimatableProperty` for any reflected, mutable component and one of its top-level fields, named by type path and field name: `get_mut` takes the component by `ComponentId` from the `AnimationEntityMut` (`get_mut_by_id`), turns it into `&mut dyn Reflect` with `ReflectFromPtr`, and downcasts the field to `A`. Its `evaluator_id` is `ComponentField((TypeId, field index))`, the one `animated_field!` hashes, so a script curve on `Transform::rotation` blends with a glTF clip's. The type path and field resolve once, when the clip is written; a field that is not `A`, or a component not `Component + Reflect`, fails naming both. This covers every reflected component field of an animatable type, `MaterialAlpha.alpha` and `Transform`'s three included, with no table to keep.
19. **A plain entity is its own player.** `PlayAnimation` on an entity with no `WorldAssetRoot` starts the frame it is added (in `apply_changed`, no `WorldInstanceReady` to wait for). `start` walks with `players` as today; when the root has no scene and the walk finds no player, it inserts `AnimationPlayer` on the root, which is then its one recorded player. It gives the root, and every descendant with a `Name` and no `AnimationTargetId`, a target id from its name path below the root (Bevy's loader convention; the root's own path is empty) and `AnimatedBy(root)`. So the player walk stays `players`/`players_in`, and parking, `cull`, `Animations` and `graph` work on a tween as on a fox. `AnimationTargetId.root` in TS is `fromNames([])`. *Alternative:* scripts insert Bevy's `AnimationPlayer`, `AnimationGraphHandle`, target id and `AnimatedBy` by hand. Rejected: a second owner of players and graphs, and node indices in TS.
20. **The clip hand-map.** A second entry in reflect-assets' hand-map list, on `&Slots` as design 12: write builds the clip from `{ curves: [[target, curve], ...], duration? }` (targets as design 12), resolving each `animatedField` through `slots.registry`; check mode validates form, types and fields only. Bevy's `add_curve_to_target` grows the duration to each curve's domain end; an unbounded curve (`forever()`) with no `duration` fails. Read is `fn(&Slots, source: Option<&Value>, &dyn PartialReflect)`: `ScriptAssets` keeps, by asset id, the JSON a script last wrote (after `assets.set`, the merged JSON), and passes it as `source`, which read returns. A clip no script wrote (`source` is `None`, a file clip) reads `{ duration, curves: null }`. Write is `fn(&Slots, base: Option<&dyn PartialReflect>, &Value)`; `assets.set` passes the current clip as `base`, so `curves: null` keeps its curves and a read then a write is the same clip. Settled with build@reflect-assets.
21. **Fades land the same frame.** material-alpha's `changed` runs in `PostUpdate` after `AssetEventSystems` and `SceneMaterialSet`, unordered with `AnimationSystems`. It gains `.after(AnimationSystems)`, so an animated `alpha` is drawn the frame it is sampled. One line in `bevy-ts-material`; no dependency is added (`AnimationSystems` is in `bevy::app`).

## Risks / Trade-offs

- [A parked root still runs `advance_transitions`, so a cross-fade under way finishes while parked] → Accept: the fade is short and the wake shows the new clip. Documented.
- [A culled clip's time stands still, so villagers that wake are out of step with where they would be] → Fine for loops; a game that cares seeks on wake. Documented.
- [The archetype move on park/wake churns if a root flickers in and out of view] → Moves happen once per change; the bench's culled arm pans a camera to measure it.
- [Breaking `repeat` for agent town] → One line in `world.tsx` when it takes the release; the proposal names it.
- [Reweighting every frame with `assets.set` costs a reflected write and Bevy's graph rebuild per frame] → Opt-in; only graph roots pay. The test measures nothing; a bench arm comes if a game reweights per frame.
- [A tween on many entities costs Bevy's per-target evaluation] → It is Bevy's own cost, and less than a TS system writing `Transform` each frame; the default (no tween) costs nothing. Measured against a TS-system tween in the fox bench's sibling arm (task 9.9).
- [`ReflectedField` reads through reflection per sample] → One `get_mut_by_id` and a field index per target per frame, resolved once; `Transform`'s fields could take Bevy's `animated_field!` directly if the bench shows a gap.
- [Stage 2 waits on reflect-assets and the hole check] → The `.animgraph.ron` path and the Rust side land first; the TS builder lands after them on this branch.
- [`seek`/`rewind`/`replay` wait on writable-native-params] → They land behind it in this change (task 4); if it slips, this change lands them later in a second commit on the same branch, never a hand-written host function.

## Migration Plan

`repeat={true}` → drop it (`Forever` is the default); `repeat={false}` → `repeat="Never"`; a level's `repeat: false` → `repeat: Never`. Rollback is reverting the change; no data or protocol state.
