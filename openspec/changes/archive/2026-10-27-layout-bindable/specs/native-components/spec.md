## MODIFIED Requirements

### Requirement: Reflect-tier TSX props take a binding
Every prop of a reflect-tier component element SHALL accept a function as well as a value (`Bindable<T>`), in the generated types and at run time: a struct's fields and a one-field tuple struct's `value` (already typed so through `ElementProps`), and an enum component's `value` (its `tsxProps`, generated by `bevy-ts types --bevy` and in `native.d.ts`). A bound prop SHALL be written through reflection over the current value when the element mounts and whenever the binding's value changes, with the same checks and errors as a plain value, raised when the value arrives. A layout-tier component's hole props bind too ("Layout-tier hole props take a binding").

#### Scenario: A bound projection type-checks
- **WHEN** a TSX file writes `<Projection value={() => (zoomed.get() ? { Orthographic: {} } : { Perspective: {} })} />`
- **THEN** `tsc` accepts it

#### Scenario: A bound projection follows its signal
- **WHEN** a scene binds `<Projection value={() => ...}>` to a signal that starts `false` (perspective), and a system sets it `true` (orthographic)
- **THEN** the camera's `Projection` is `Perspective` before the set and `Orthographic` after the next update, and setting it back writes `Perspective` again

#### Scenario: A bad bound value
- **WHEN** the binding returns `{ Isometric: {} }`
- **THEN** the error names `Projection` and its variants, as for a plain value

## ADDED Requirements

### Requirement: Layout-tier hole props take a binding
Every hole prop of a layout-tier component element (a hole reflection can write: a `Color`, an enum with data, an `Option`, a nested struct, a list, set or map, a `Handle<T>`, an opaque type with reflected serde) SHALL accept a function as well as a value, in the generated types (`tsxProps` from `bevy-ts types --bevy` and `native.d.ts`, each field typed `T | (() => T)`) and at run time. A bound hole SHALL be written through `bevy_ts::reflect_value`, by its Bevy field name, when the binding's value changes, with the same checks and errors as a plain value, raised when the value arrives; until its first value arrives the hole keeps the component's default. A binding that returns the value last written SHALL write nothing. A hole whose type is on the uncovered list SHALL fail the load whether it is bound or not, with the list's reason. No hole kind SHALL need code of its own.

#### Scenario: A bound fog colour type-checks
- **WHEN** a TSX file writes `<DistanceFog color={() => (night() ? "#101020" : "#c0d0ff")} />` and `<DistanceFog color={() => 3} />`
- **THEN** `tsc` accepts the first and reports an error on the second

#### Scenario: A bound fog colour follows its signal
- **WHEN** a scene binds `<DistanceFog color={() => ...}>` to a signal that starts `false` (`#c0d0ff`), and a system sets it `true` (`#101020`), then `false` again
- **THEN** the camera's `DistanceFog.color` is `#c0d0ff` before the set, `#101020` after the next update, and `#c0d0ff` after the second set, and its column fields (`directional_light_exponent`) keep their values

#### Scenario: A bad bound hole value
- **WHEN** the binding returns `{ Srgba: { red: 1 } }`
- **THEN** the error names `DistanceFog.color` and the missing channels, as for a plain value, and the colour keeps its last good value
