## ADDED Requirements

### Requirement: Reflect-tier TSX props take a binding
Every prop of a reflect-tier component element SHALL accept a function as well as a value (`Bindable<T>`), in the generated types and at run time: a struct's fields and a one-field tuple struct's `value` (already typed so through `ElementProps`), and an enum component's `value` (its `tsxProps`, generated by `bevy-ts types --bevy` and in `native.d.ts`). A bound prop SHALL be written through reflection over the current value when the element mounts and whenever the binding's value changes, with the same checks and errors as a plain value, raised when the value arrives. A layout-tier component's hole props (`<DirectionalLight color>`) SHALL stay values: typed without a function, and a binding that reaches the runtime SHALL fail the load naming the type and the prop, as now.

#### Scenario: A bound projection type-checks
- **WHEN** a TSX file writes `<Projection value={() => (zoomed.get() ? { Orthographic: {} } : { Perspective: {} })} />` and `<DirectionalLight color={() => "#fff"} />`
- **THEN** `tsc` accepts the first and reports an error on the second

#### Scenario: A bound projection follows its signal
- **WHEN** a scene binds `<Projection value={() => ...}>` to a signal that starts `false` (perspective), and a system sets it `true` (orthographic)
- **THEN** the camera's `Projection` is `Perspective` before the set and `Orthographic` after the next update, and setting it back writes `Perspective` again

#### Scenario: A bad bound value
- **WHEN** the binding returns `{ Isometric: {} }`
- **THEN** the error names `Projection` and its variants, as for a plain value
